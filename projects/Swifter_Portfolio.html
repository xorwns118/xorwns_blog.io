Swifter

60초 안에 캐릭터를 좌우로 빠르게 분류하고, 연속 정답 콤보로 점수를 끌어올리는 하이퍼 캐주얼 판단 퍼즐입니다.

Unity 2022.3 C# Android / iOS Google Play Games Game Center AdMob

프로젝트 한눈에 보기

액션 퍼즐 미니게임의 핵심 감각을 모바일 터치 조작에 맞춰 다시 구성했습니다. 짧은 라운드, 즉시 판정, 콤보 보상, 로컬 기록 저장까지 게임 루프를 완성한 프로젝트입니다.

역할

개인 프로젝트로 게임 로직, UI 흐름, 사운드, 로그인, 광고, 빌드 설정을 직접 구현했습니다.

검증 결과

Google Play Console과 App Store Connect에 앱을 업로드하고 스토어 심사/배포 흐름을 경험했습니다.

현재 상태

라이브 광고 검증 후 Android는 비활성화했고, iOS는 개발자 멤버십 해제로 현재 스토어 노출 상태가 아닙니다.

60초 한 판 제한 시간
10개 미리 생성되는 캐릭터 큐
+콤보 연속 정답 기반 점수 누적
2개 Google Play / App Store 업로드 경험

시스템 아키텍처

씬 전환은 전용 매니저가 요청을 받고 LoadingScene을 거쳐 다음 씬을 비동기로 여는 구조입니다. 플레이 중에는 입력과 셔플 기준을 바탕으로 노드를 판정하고, 기록과 사운드 설정은 로컬에 저장하며 로그인과 광고는 플랫폼 SDK와 연결했습니다.

구조 요약: 씬 흐름 -> 코어 매니저 -> 플레이 로직 -> 로컬 데이터 / 플랫폼 SDK

플레이 루프

중앙 라인의 첫 캐릭터가 왼쪽 그룹인지 오른쪽 그룹인지 판단해 버튼을 누릅니다. 정답을 이어갈수록 콤보가 점수로 바로 돌아오고, 실수하면 흐름이 끊깁니다.

그룹 셔플

시작 시 캐릭터 6개를 섞어 좌우 그룹에 나누고, 각 그룹의 태그 목록을 판정 기준으로 저장합니다.

큐 생성

중앙 라인에는 10개의 캐릭터가 스케일과 정렬 순서를 달리해 쌓이며, 다음 입력 대상을 미리 보여줍니다.

즉시 판정

좌우 버튼 입력과 캐릭터 태그를 비교해 정답이면 이동 코루틴을 실행하고 새 캐릭터를 보충합니다.

기록 저장

시간 종료 후 현재 점수와 최대 콤보를 비교해 최고 기록을 PlayerPrefs에 저장합니다.

NodeManager.cs · 정답 판정과 콤보 점수

맨 앞 캐릭터의 태그가 선택한 그룹에 포함되면 콤보를 올리고, 콤보 수만큼 점수를 더합니다.

if ((isLeft && ShuffleManager.I.leftCharacters.Contains(characterList[0].tag))
    || (!isLeft && ShuffleManager.I.rightCharacters.Contains(characterList[0].tag)))
{
    GamePlayManager.I.combo++;
    GamePlayManager.I.comboTime = 1.0f;
    GamePlayManager.I.score += GamePlayManager.I.combo;

    characterList.RemoveAt(0);
    RandomChar();
}
else
{
    StartCoroutine(WrongWay());
    GamePlayManager.I.combo = 0;
}

중앙 라인에는 10개의 캐릭터를 미리 쌓고, 뒤쪽 캐릭터일수록 작게 보여 다음 입력 흐름을 예고합니다.

기술 구현

플랫폼별 로그인과 AdMob 광고를 연동하고, 설정 저장, 비동기 씬 로딩, 사운드 제어를 구현했습니다.

플랫폼별 인증

Android는 Google Play Games, iOS는 Game Center를 사용하며 전처리기로 코드를 분리했습니다. 실패 시 게스트 모드로도 진입할 수 있습니다.

콤보 점수 시스템

정답마다 콤보를 올리고 score += combo로 점수를 누적해, 같은 60초 안에서도 정확도와 속도가 함께 드러나게 했습니다.

비동기 로딩

전용 로딩 씬에서 LoadSceneAsync와 이미지 fillAmount 보간을 사용해 씬 전환 흐름을 부드럽게 처리했습니다.

광고와 설정

AdMob 전면 광고, BGM/효과음 토글, 개인정보 처리방침 링크, 최고 기록 저장까지 모바일 서비스의 기본 요소를 구성했습니다.

LoginManager.cs · 플랫폼별 로그인 분리

하나의 로그인 매니저에서 플랫폼별 SDK 코드를 전처리기로 나누어 Android와 iOS 빌드를 분리했습니다.

#if UNITY_ANDROID
public void Start()
{
    PlayGamesPlatform.Instance.Authenticate(ProcessAuthentication);
}
#elif UNITY_IOS
void Start()
{
    AppleLogin();
}
#endif

AdManager.cs · 광고 종료 후 복귀 흐름

전면 광고가 닫히거나 열리지 못했을 때 광고를 다시 로드하고 메인 화면으로 복귀하게 처리했습니다.

interstitialAd.OnAdFullScreenContentClosed += () =>
{
    LoadInterstitialAd();
    SceneController.I.MainScene();
};

interstitialAd.OnAdFullScreenContentFailed += (AdError error) =>
{
    LoadInterstitialAd();
    SceneController.I.MainScene();
};

스토어 업로드와 광고 검증

로컬 빌드에서 끝내지 않고 Google Play Console과 App Store Connect에 실제 업로드해 심사와 배포 흐름을 확인했습니다. 테스트 광고 확인 후 스토어 배포 상태에서 실제 광고 연결까지 검증했습니다.

Google Play

버전 코드 25, 버전 1.0을 프로덕션 트랙에 올렸고 2025년 2월 26일 Google Play 제공 상태를 확인했습니다.

App Store

iOS 버전 1.0을 App Store Connect 심사 흐름에 제출했고 2025년 2월 26일 배포 준비됨 상태까지 진행했습니다.

실기기 광고 확인

별도 테스트 기기에서 테스트 광고를 먼저 확인한 뒤, 배포 상태에서 라이브 광고가 정상 노출되는지 검증했습니다.

현재 상태

광고 검증 후 Android는 비활성화했고, iOS는 Apple Developer Program 멤버십 해제로 현재 스토어 노출 상태가 아닙니다.

개발 중 해결한 문제

모바일 빌드와 SDK 연동 과정에서 발생한 인증 및 의존성 문제를 추적하고, 앱 서명 인증서, 플러그인 버전, Android 빌드 설정을 점검했습니다.

  • GPGS 로그인 취소 상태앱 서명 키 인증서 지문 누락으로 인증이 취소되던 문제를 Google Cloud Console 설정 확인으로 추적했습니다.
  • Gradle 의존성 충돌Google Play Games, AdMob, External Dependency Manager 버전 차이에서 발생하는 빌드 오류를 점검했습니다.
  • Target SDK 설정Android Version이 의도와 다르게 적용될 때 ProjectSettings 값을 확인하고 Unity 재실행 후 빌드하는 흐름을 기록했습니다.
  • AdMob ID 구분앱 ID와 광고 단위 ID의 형식 차이를 분리해 광고 초기화와 로드에 필요한 값을 정리했습니다.
  • Unity 생명주기 정리Awake, Start, Update와 코루틴 실행 시점을 구분해 매니저 초기화와 게임 진행을 나눴습니다.
  • 런타임 참조 관리SerializeField, GetComponent, 씬 검색 API의 비용 차이를 의식하며 필요한 참조를 관리했습니다.
